02注意力：Transformer 里最关键的部件

注意力让每个词回头看其他词，并决定该重视谁。用一句话就能体会它的必要性——

点任意一个词，看它会「注意」谁——箭头就是注意力连线，线越粗权重越大：
点一下 it 试试——这个句子是理解注意力最好的例子。

Q、K、V 是三个矩阵，不是三个词

每个 token 的向量都乘上三个可学习矩阵，得到三份表示。注意力 = 用 Q 和 K 算权重，再用权重加权求和 V。 下面用同一个句子展示这三个矩阵的样子（数值为示意，列数简化）。

Attention(Q, K, V) = softmax( QKᵀ / √dk ) · V

Q · Query（我在找什么）

Q = X · WQ，「it」这一行的 Q 会去和所有 K 比对。

K · Key（我是什么）

K = X · WK，每个词提供一个「标签」供 Q 匹配。

V · Value（我能提供什么内容）

V = X · WV，权重算出来之后，最终取的就是 V 的加权和—— Q 和 K 只决定"看谁"，V 才是被拿走的实际信息。

句子是：「The animal did not cross the street because it was too tired.」
问题：it 指的是 animal 还是 street？我们人类秒懂是 animal——因为街道不会累。
模型要答对，就必须让 it 的 Q 和 animal 的 K 高度匹配。这就是注意力在做的事。

Q / K / V 是什么

每个词投影成三份：Query（我在找什么）、Key（我是什么）、Value（我能提供什么）。 用 Q 和所有 K 算相似度得到权重，再加权求和 V。

Attention(Q,K,V) = softmax(QKᵀ/√dk) · V

因果掩码

LLM 里每个词只看自己和之前的词，不看后面。因为生成时后面的词还不存在—— 这保证训练和推理行为一致。

03LLM 进化史：两条路线的博弈

2017 年那道分岔口之后，OpenAI 走「生成」、Google 走「理解」，双方互相借鉴、各自推进。 下面这张 DAG 画出两条血脉的演进与交汇——点任意节点看详情。

OpenAI · GPT 线（decoder-only，生成） Google · BERT 线（encoder-only，理解） Google 另一分支（enc-dec） 后续/开源生态
读法：箭头表示技术继承或直接借鉴。点任意圆角矩形节点，这里会展开它改变了什么。
这场博弈的结果不是"一方淘汰另一方"：
· 架构上，decoder-only 赢了主流——但它的"预训练 + 单目标"范式，正是 BERT 那一套被证明可通用化之后的产物。
· 方法上，掩码预训练（BERT）没有消失，而是变成了 LLaDA 这类扩散语言模型的训练目标，回流到了生成路线。
· 能力上，Google 的 enc-dec（T5/BART）在翻译、摘要这类"输入输出不对等"的任务上仍然高效。

04Transformer 变种图谱：引擎被改装成了什么

原始 Transformer 只是个起点。为了跑得更快、吃更长的上下文、装下更大的知识， 它被拆开重组出几十个变种。下面按改装的位置归类——点任意变种看它改了什么。

看图的方法：所有变种都只动了三处之一——注意力怎么算（稀疏 / 线性 / 滑动窗口）、 KV 怎么存（GQA / MLA）、FFN 怎么组织（MoE）。 主干（残差 + LayerNorm + 预测下一个 token）几乎没变过。
一个容易误判的点：Mamba、RWKV 这类严格说已经不是 Transformer——它们拿掉了注意力， 改用状态空间或线性递推。放在这里是因为它们处在同一场竞争里，且常被拿来改造 Transformer （例如 Jamba 把 Mamba 层和注意力层拼在一起）。说「Transformer 变种」时最好加个引号。

05三种架构：谁更适合干什么

同一个 Transformer，只保留一部分就得到三种不同的架构。它们的能力侧重完全不同—— 这也是 BERT 和 GPT 分野的根源。

Encoder-Decoder

先破除一个常见误解：BERT、GPT、T5 并不是三种不同的网络结构—— 它们的 transformer 层完全一样，唯一的差别是那一行 attention mask。 BERT 用双向掩码（能看右边）、GPT 用因果掩码（只能看左边）、T5 的编码器双向而解码器因果。 一个 mask 就分出了三个阵营。
任务推荐架构代表模型
文本分类 / 情感分析Encoder-onlyBERT、RoBERTa
命名实体识别Encoder-onlyBERT、RoBERTa
抽取式问答Encoder-onlyBERT
文本生成 / 创作Decoder-onlyGPT、LLaMA
翻译Encoder-DecoderT5、BART
摘要Encoder-DecoderBART、T5
生成式问答Enc-Dec 或 DecoderT5、GPT
为什么今天几乎只剩 decoder-only？因为当模型足够大时， 「预测下一个 token」这一件事就能承载所有任务——翻译、分类、问答都可以写成生成问题。 一个架构通吃，工程上最省。但在需要深度理解输入的场景，encoder-only 依然高效便宜。

07它真正在做的：猜下一个词

抛开花哨能力，核心只有一个动作：给定一段文字，预测最可能的下一个 token。 但它不是只挑一个——它给每种可能都算一个概率。

输入： The sky is ▊
点一下看看。模型不会给出唯一答案，而是给整张概率表——最后按概率抽样挑一个。

为什么不是「查表」

它不是从数据库找答案，而是基于学到的语言规律算出「什么词最像该出现的」。第 11 节解释幻觉时会再用到。

08逐词生成：一整段话是怎么流出来的

既然只会猜一个词，长回答从哪来？答案朴素得有点好笑：猜一个 → 接到后面 → 再猜， 循环到模型决定停下。这叫自回归（autoregression）。

所以「打字机效果」不是装饰——它就是这个循环的真实节奏。长回答 = 高速重复的下一个词预测。

09训练原理：一场猜词游戏，玩上万亿次

新模型的参数全是随机数，一开始的预测纯属胡言。它是怎么学会的？ 靠一场极简的游戏——而题目和答案都是现成的。

损失（预测错得有多离谱）88%

为什么不用人工标注

遮住最后一个词，正确答案本来就在原文里。文本自带题库，这才是它能用上万亿 token 的原因。

「调整数字」怎么调

反向传播把错误往回追，梯度下降让每个参数朝「减少错误」的方向挪一点。 重复亿万次，随机网络就变成了语言模型。

10主流训练范式：从续写到对齐

训练不是一步完成的。从「会说话」到「好好说话」，中间有好几个阶段，每个阶段解决不同的问题。

Pre-training 预训练第一阶段
在数万亿 token 上玩猜词游戏。目标是学会语言规律和世界知识。
产出物是一台「文本续写机」——知识很多，但还不懂怎么当助手。
典型规模：万亿级 token · 数千张 GPU · 数月
SFT 监督微调第二阶段
用人工精心编写的「指令 → 回答」样例继续训练。 教它遵循指令、按人类期望的方式回答。
这是从"续写机"变成"助手"的关键一步。
典型规模：数万到数百万条高质量样例
RLHF 人类反馈强化学习对齐
让人类对多个回答排序打分，训练一个奖励模型，再用强化学习让 LLM 学着产出高分回答。 解决"什么算好回答"这个难以用规则描述的问题。
代表：InstructGPT · 让 ChatGPT 真正好用
DPO 直接偏好优化对齐 · 更轻
RLHF 的简化替代：跳过奖励模型和强化学习，直接用偏好数据优化模型。 训练更稳、成本更低，近年被广泛采用。
相比 RLHF：少一个模型、少一套 RL 训练流程
一句话区分：预训练给它知识，SFT 教它格式，RLHF / DPO 调它偏好。

各阶段对照

阶段数据解决什么产出
预训练海量无标注文本知识 + 语言能力续写机
SFT指令-回答对听指令、答对格式基础助手

11上下文窗口：它的短期记忆

每个 LLM 都有上限：一次最多能看多少 token。这叫上下文窗口，相当于模型的短期记忆。

🟦 窗口内：模型能看见 ⬛ 滚出去了：模型看不见（已被丢弃）
这解释了一个常见现象：聊得特别久之后，模型忘了你最开始说过什么。 不是它「不用心」，而是那部分内容已经掉出窗口，物理上不可见了。
